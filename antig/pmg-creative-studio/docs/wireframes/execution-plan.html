Technical Architecture
System design · data flow · integrations
Client Layer
Canvas Editor
Fabric.js React Zustand
Select, drag, resize, layers. Holds design as JSON object in memory.
Batch Editor UI
Next.js React Tailwind
Slot manager, combination math, live generation grid with progress tracking.
Template Picker + Brand Kit
Next.js React
Browse templates, auto-load client brand profile, filter by size/type.
↓
Application Layer
Auth + Routing
Clerk
User auth, client-scoped routing, session management.
API Layer
Next.js API Routes
Design CRUD, template CRUD, brand kit, batch job submission.
Job Queue Manager
BullMQ Redis
Submit render jobs, track status (queued → running → done), retry on failure.
Alli API Connector
REST
Pull brand profiles, client data, campaign structure. Source of truth for all client metadata.
↓
Worker Layer (background processes)
HTML → Image Worker
Puppeteer
Renders JSON template + variant data to HTML → screenshots to PNG. Containerized, horizontally scalable.
AI Image Worker
Replicate Flux Schnell
Text-to-image generation. Flux 1.0 for quality, Schnell for speed. Flux.1 Kontext for image editing.
AI Copy Worker
Claude API
Headline + description generation. Prompt includes brand guidelines, product context, platform constraints.
BG Removal Worker
rembg Remove.bg
Segment and remove product image backgrounds. Self-hosted for cost at scale.
Video Worker
Phase 4
Same BullMQ queue, different worker type. Creatify or custom FFmpeg pipeline.
↓
Persistence Layer
PostgreSQL
Primary DB
users, clients, templates, designs (JSON), brand_kits, variants, render_jobs, creative_lineage.
Redis
Job queue + cache
BullMQ job state, render progress events, session cache, brand kit short-term cache.
S3 / Cloudflare R2
Object storage
Asset uploads, generated images, exported PNGs/ZIPs, HTML template files. Signed URLs for delivery.

Risk Matrix
5 risks · severity + mitigation
Template library empty at launch
HIGH
If creative teams open the tool and find no templates matching their active clients, they will not use it again. First impression is permanent in internal tooling.
Commission 20 templates in Phase 0 as a sprint-0 gate. Do not open Phase 1 until 15+ templates exist. Designate a permanent template author role now.
Render output doesn't match approved ads
HIGH
Client-approved creative has a specific look. If the Puppeteer render produces even slightly different font rendering or layout, it won't pass QA and the tool can't be used on real accounts.
In S4, render existing approved ads through the new pipeline and diff against originals. Make pixel accuracy a gate before Phase 1 sign-off.
Batch generates bad combinations
HIGH
Without exclusion rules, media teams see obvious mismatch pairings (luxury headline + clearance image). They curate manually. The tool created work instead of saving it.
Ship exclusion rules in S5, same sprint as the combination engine. Not post-MVP — it's part of the batch MVP definition.
No designated template author
MEDIUM
The CRM team built templates before. If ownership of new template creation is ambiguous, template production will stall and the library will never grow past launch content.
Designate a template author in Phase 0. Build the template authoring UI (Phase 4) so it doesn't require engineering to produce new templates.
Feedback loop never gets built
MEDIUM
Without performance data connected to creative output, the tool is a render machine. It competes with Canva, not with a creative intelligence platform. Differentiation erodes.
Add perf_ctr field to variants table now. Build Alli data connector in Phase 4 (within 90 days of Phase 2 launch). Write the spec before Phase 2 ships.

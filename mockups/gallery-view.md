# Creative Gallery — Design Spec

Companion to `gallery-view.html`.

---

## What it is

The Creative Gallery is a shared view for every team member working on a client. It surfaces all generated outputs across all AdLabs apps in one place — Ad Resizing, Template Builder, Batch Variants, Resize Image — without requiring the user to open each app individually to find something.

The primary use case is **audit and retrieval**: a strategist or creative lead wants to see what was generated for Ralph Lauren this week, find the right version, and either download it or jump back into the app that made it.

---

## Data model

Each generative app writes outputs to a shared Firestore path:

```
clients/{clientSlug}/apps/{appId}/outputs/{outputId}
clients/{clientSlug}/apps/{appId}/creatives/{creativeId}
clients/{clientSlug}/apps/{appId}/batches/{batchId}/results/{resultId}
```

The gallery aggregates across all `appId` values for the selected client:

| App | appId |
|---|---|
| Ad Resizing | `ad-resizing` |
| Template Builder | `template-builder` |
| Batch Variants | `batch-variants` |
| Resize Image | `resize-image` |

Each output document carries: `status`, `storageRef`, `batchId`, `dimension`, `createdAt`, and a reference to the source creative that spawned it.

### Version inheritance

When a user reruns generation on the same source creative (same input image, same target size), each run produces a new output document. These outputs are siblings — same source, same dimension — and are grouped into a **version chain**:

```
source_image.png
  └── 1080×1920
        ├── v1  (batch_a1b2c3, May 13)
        ├── v2  (batch_d4e5f6, May 14)
        └── v3  (batch_4f3a9c, May 15)  ← latest
```

The gallery surfaces this grouping rather than showing three separate tiles for the same creative slot.

## Filter bar

The three dropdown filters are independent and additive:

| Filter | Options |
|---|---|
| App | All apps, Ad Resizing, Template Builder, Batch Variants, Resize Image |
| Date range | Today, Last 7 days, Last 30 days, Custom range |
| Status | All statuses, Completed, Generating, Failed |

Search filters by source creative filename or batch ID, client-side across the visible date window.

The active filter (if any) renders as a solid blue button (primary style). Inactive filters are tertiary (white + ring border).

---

## Gallery grid

Outputs are grouped by calendar date, newest first. Within each date group, outputs are sorted by `createdAt` descending.

Each tile shows:
- Thumbnail (placeholder image or actual `storageRef` render)
- Source filename (truncated)
- App badge (colored dot + app name)
- Dimension or version count (see below)
- Status badge (Done, Generating, Failed) — positioned top-right of thumbnail
- Hover overlay with Preview and Download actions

**Failed tiles** render desaturated with a red wash. They are still clickable (the lightbox shows the error context and retry option).

**Generating tiles** show a spinner badge and no hover actions until complete.

---

## Version stacking

Tiles that belong to a version chain are visually distinguished:

- A **paper-stack effect** (two offset shadow cards behind the tile) signals "more than one version exists here"
- The bottom-right of the tile shows a **version count badge** (`2 versions`, `3 versions`) in place of the dimension label
- Single-version tiles show the dimension label as normal

This communicates version depth at a glance without cluttering the grid.

## Lightbox

Clicking any completed tile opens the lightbox: a full-screen modal with a dark image canvas on the left and a detail panel on the right.

### Single-version tile lightbox

```
[ ← ]  [large image preview]  [ → ]     |  Source creative
                                         |  campaign_summer_hero.png
                 1 of 4 · Today          |  ─────────────────────────
                                         |  Generated by   Ad Resizing
                                         |  Dimensions     728 × 90 px
                                         |  Generated      May 15 · 10:42 AM
                                         |  Status         ● Completed
                                         |  Batch          batch_4f3a9c
                                         |  ─────────────────────────
                                         |  [ Download PNG ]
                                         |  [ Open in Ad Resizing → ]
```

### Versioned tile lightbox

When the tile has a version chain, the detail panel gains a **Versions strip** at the top:

```
VERSIONS
[ Source ]  [ v1 ]  [ v2 ]  [ v3 (latest) ]   ← thumbnails, active highlighted blue
```

Clicking a thumbnail:
- Updates the main image canvas to show that version
- Updates the "Version" metadata row: `v3 of 3 · latest`
- Does not navigate away; the source filename and batch ID update in place

The "Version" row is not shown for single-version tiles.

### Compare to source

A **"Compare to source"** button lives in the image canvas (bottom-right corner). Available only on versioned tiles.

Toggling it switches the image canvas from a single centered image to a **split-pane view**:

```
|      Source       |      Version 3 (latest)      |
|   [source image]  |      [generated image]        |
```

Each pane has a floating label. The divider is a subtle white line. Toggling again restores the single-image view.

The compare button label changes to "Exit compare" while in split mode.

## Implementation notes

### Firestore query

The gallery needs a cross-collection fan-out query. Recommended approach: a denormalized `gallery_outputs` collection at `clients/{clientSlug}/gallery_outputs/{outputId}` written to by each app's cloud function on output completion. Fields: `appId`, `status`, `storageRef`, `sourceRef`, `dimension`, `batchId`, `createdAt`, `versionOf` (optional reference to first version in chain).

This avoids N parallel collection group queries and gives a single ordered stream to paginate.

### Version grouping

Group by `(sourceRef, dimension)` key. All outputs sharing the same source and dimension are in one version chain. Sort by `createdAt` ascending to assign v1, v2, v3 ordinals. Display the latest (highest ordinal) as the tile face.

### Routing

The gallery lives at `/adlabs/{clientSlug}/gallery`. The "Open in {App}" button in the lightbox deep-links to `/adlabs/{clientSlug}/{appId}` with the batch ID as a query param, letting the app restore that session.
